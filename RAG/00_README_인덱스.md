## 챗봇 앱 연동 방식

이 프로젝트는 관리자 챗봇설정(관리 콘솔)과 위젯(사용자 화면)이 분리된 멀티페이지 Streamlit 앱(`main.py` + `app_pages/`)이며, 검색·RAG 로딩 등 실제 로직은 `utils/engine.py`에 있습니다. 앱은 이 폴더의 `01`~`05` 파일을 `##`/`###` 헤더 단위로 자동 파싱해 지식베이스 청크로 로드하고, 관리자 챗봇설정의 "RAG 관리 > 보충 데이터 관리"에서 관리자가 직접 입력한 Q&A(`data/knowledge_base.json`)와 합쳐서 검색합니다. 검색 자체는 임베딩이 아니라 **문자 바이그램 유사도 + IDF 가중 키워드 일치 기반**이며, `06_동의어사전_변경이력.md`의 동의어 표를 이용해 사용자 질문을 검색 전에 보강(동의어 치환)합니다. 따라서:

- 새 정보를 추가할 때는 반드시 `##` 또는 `###` 헤더로 구분된 하나의 독립된 항목으로 작성하세요. 헤더가 없는 긴 문단은 하나의 거대한 청크로 묶여 검색 정확도가 떨어집니다.
- 자주 다르게 표현되는 질문(사투리, 줄임말, 유사어)이 있다면 해당 항목 바로 아래에 `*(관련 검색어: ...)*` 줄을 추가하거나 `06` 파일의 동의어 사전에 행을 추가하세요.
- `.md` 파일을 직접 편집하는 대신, 관리자 챗봇설정 "RAG 관리 > 보충 데이터 관리 > PDF 업로드로 보완"에서 조사한 자료(PDF)를 올리면 문장 단위로 자동으로 나눠 `data/knowledge_base.json`에 등록해줍니다. 등록 전 몇 개 조각으로 나뉘는지 미리 확인할 수 있습니다.
- "RAG 관리 > RAG 분석" 탭에서 특정 항목(또는 전체)을 골라 청크 수·길이 분포·항목 간 유사도 분포도를 시각적으로 점검할 수 있습니다. 청크가 너무 길거나 짧은지, 카테고리별 균형이 맞는지 확인할 때 유용합니다.

## 자기 참조형 사용량 최적화 (연결된 LLM 성능이 낮아도 RAG만으로 정확히 답하기 위한 장치)

연결된 LLM의 답변 다듬기 품질에 기대지 않고도 정확히 답하려면, **실제로 자주 쓰이는 항목이 무엇인지 파악하고 그 정보를 원본 문서 자체에 남겨두는 것**이 중요합니다. 이를 위해 다음과 같은 자기 참조(self-referential) 루프가 동작합니다.

1. 위젯에서 방문자가 질문할 때마다, 검색되어 실제로 사용자에게 보여진 청크의 참조 횟수를 `data/rag_usage.json`에 기록합니다(관리자 챗봇설정의 "챗봇 테스트" 화면 사용은 통계에 포함되지 않습니다).
2. 하루 한 번(앱이 그날 처음 열릴 때, 또는 관리자 챗봇설정에서 수동 실행 시) 그 누적 횟수를 각 항목의 헤더 바로 아래에 `*(참조 횟수: N회 · 참조율: X% · 마지막 참조: 날짜)*` 형태로 자동 삽입/갱신합니다. **이 줄은 자동 생성/관리되므로 직접 수정하지 마세요** — 다음 최적화 실행 시 값이 다시 덮어써집니다.
3. 같은 실행에서 `99_사용현황_리포트.md`를 새로 생성해 자주 참조된 항목 TOP, 한 번도 참조되지 않은 항목, 처리 대기 중인 미응답 질문을 한눈에 보여줍니다.
4. RAG에서 답을 찾지 못한 실제 질문은 `data/unanswered_questions.json`에 쌓이며, 관리자 챗봇설정 "RAG 관리 > 미응답 질문" 탭에서 관리자가 인터넷 검색 등으로 조사한 뒤 답변을 등록할 수 있습니다. 등록 즉시 검색에 반영됩니다.

앱이 상시 실행되는 서버가 아니므로, 아무도 접속하지 않는 날에도 최적화가 이뤄지길 원한다면 `scripts/daily_optimize.py`를 OS 스케줄러(Windows 작업 스케줄러 등)에 등록하세요.

## RAG 구축(운영) 시 권장 사항

1. **청크(chunk) 단위**: 각 `##` / `###` 헤더가 곧 하나의 청크입니다. 특히 `03_자주묻는질문_FAQ.md`는 `###` 단위(질문 1개)가 청크 1개가 되도록 설계되어 있습니다.
2. **`03_자주묻는질문_FAQ.md`를 최우선 검색 대상으로 설정**하세요. 실제 방문객이 가장 많이 묻는 질문과 공식 답변이 원문 그대로 담겨 있습니다.
3. **"⚠️ 중요" 섹션(반려동물/안내견 규정)은 별도 청크로 분리되어 있으며, 서로 다른 결론(불가 vs 가능)을 명확히 구분**해 놓았습니다. 새 항목을 추가할 때도 서로 반대되는 결론을 가진 내용을 한 청크에 섞지 마세요.
4. **모든 청크는 자기완결형(self-contained)으로 유지**하세요. "위 OO 섹션 참고"처럼 다른 청크를 가리키기만 하는 답변은, 그 청크만 단독으로 검색되었을 때 사용자에게 쓸모없는 답이 됩니다. 실제로 이런 셀프 참조 패턴이 다수 발견되어 이번 개정에서 모두 실제 답변으로 교체했습니다.
5. **답변 텍스트가 비어 있던 항목**은 다른 페이지의 교차 정보로 채우거나(예: 태극열차 승차 위치, 종합안내센터 위치), 정보 자체가 없는 경우 "정확한 위치는 종합안내센터(041-560-0771)로 문의해주세요"처럼 안전하게 안내하도록 이미 채워두었습니다. 새로 추가하는 항목도 이 원칙을 따르세요.
